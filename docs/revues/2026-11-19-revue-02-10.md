# Revue de code des exercices 02 à 10 (19/11/2026)

Deux relecteurs indépendants, chacun sur une moitié du code écrit depuis 01 :
- **domaine Either** : `duplojs/either/`, `duplojs/curried.ts`, `type/union/` ;
- **expressions et types** : `expression/`, `type/`, `shared/`, `duplojs/common/pipe`, `duplojs/array/`, `duplojs/string/`, `return`, `variable`, `build`.

Ils ont reçu le code, pas les conclusions de l'auteur, et ont exécuté de petits programmes pour confirmer leurs constats.

## Constats confirmés et corrections

| # | Constat | Exemple qui échouait | Correction (générale) |
|---|---|---|---|
| 1 | **Ordre d'évaluation** dans les littéraux de tableau et les gabarits : un élément avec calcul préalable (ternaire…) s'exécutait avant les éléments précédents | `[p(1), f() ? p(2) : 0]` affichait `2 1` au lieu de `1 2` | `shared/sequence.ts` : `sequenceEvaluations` range un élément dans une variable s'il est suivi d'un élément qui a des calculs préalables |
| 2 | **Ordre d'évaluation** dans `matchInformation` / `whenIsRight` : les fonctions étaient évaluées avant l'entrée | `matchInformation(compute(), { a: makeHandler("x") })` appelait `makeHandler` d'abord | l'entrée est rangée avant les fonctions, comme dans `rightPipe` |
| 3 | **Valeur non convertie vers le paramètre déclaré** par la fonction (`rightPipe`, `whenIsRight`, `group`) : Go ne compilait pas | `rightPipe(f(3), (v: number \| string) => …)` | les fonctions passées en valeur sont typées par **leur propre signature** (`getFunctionValueTypes`, signature du contexte si elle est générique) ; `callFunctionValue` convertit l'argument |
| 4 | **Union vers union** non traduite | `whenIsRight(parse(3), (v) => small(v))` : `Union2 → Union3` | `convertToType` : fonction appelée sur place, une branche par variante source ; union → un membre : `x.Vi` (base du rétrécissement de 11) |
| 5 | `matchInformation` exigeait un type de paramètre **identique** | gestionnaire `(v: number \| string) => …` | candidats retenus si la valeur est **convertible** (`canConvertToType`) |
| 6 | **Nom déstructuré inutilisé** : Go refuse la variable | `([one, two]) => one` | `_ = name` après chaque liaison |
| 7 | **Déstructuration d'un tableau TS** (`number[]`) : panique Go là où JS donne `undefined` | `([a, b]: number[]) => …` | erreur nommée `un-support-binding-from-array` ; seuls les tuples `[N]T` (longueur garantie) sont déstructurés |
| 8 | **Opérateurs sur les bits** : Go non compilable | `7 << 1` | erreur nommée `un-support-bitwise-operator` |
| 9 | **Concaténation chaîne + nombre** : Go non compilable | `"n=" + count` | l'autre opérande est converti comme `DString.to` |
| 10 | `**` et parenthèses : `notfound-transformer` | `2 ** 10`, `(1 + 2) * 3` | `math.Pow` ; `(x)` → `x` |
| 11 | Tri des membres d'union avec `localeCompare` : dépend de la locale de la machine | — | comparaison par unités de code |
| 12 | Identifiant généré pour rien dans `group` | — | supprimé |

Outils partagés nés de la revue (dans `duplojs/either/dispatch.ts`) : `FunctionValue`, `callFunctionValue`, `getFunctionValueTypes`, `getRightValueType`. `rightPipe` et `whenIsRight` ont perdu leur propre copie de ce code.

Tests : nouvelle fixture `review-regressions` (`tests/transpiler/reviewRegressions.test.ts`) qui rejoue chacun de ces cas et compare Go à TS à l'exécution. 33 tests sur 33 au vert, `go vet` propre sur 00 à 10.

## Constats laissés ouverts (documentés)

| Constat | Pourquoi pas maintenant |
|---|---|
| `Promise` reconnue par son nom | « shortcut » déjà signalé dans `type/promise.ts` |
| seule la première signature d'une fonction surchargée est lue (`getDeclaredParameterCount`) | aucun exercice ne passe de fonction surchargée en valeur |
| variantes `ok`, `none`, `some`, `result` de DuploJS absentes du registre | aucun exercice ne les utilise ; elles seraient traitées comme des valeurs ordinaires |
| `group` sur un élément qui n'est pas un Either : DuploJS l'enveloppe dans `success` | les types TS l'interdisent |
| code inatteignable (`go vet`) après une étape de `rightPipe` qui est toujours un `Left` | non reproduit |
| `notfound-transformer` pour une affectation (`x = x + 1`) | erreur générique existante, pas une erreur nommée |
| `bindOnce` ne copie pas un identifiant : un calcul suivant qui le modifierait changerait la valeur lue | inatteignable tant que l'affectation n'est pas traduite (commentaire `shortcut:` dans `shared/sequence.ts`) |
| `"x" + true`, `m + "s"` avec `m: number \| string` | erreur nommée `un-support-concatenation-type` |

## Relecture des corrections

Le diff des corrections a lui-même été relu : aucun problème sérieux. Le relecteur a recoupé avec JS des cas supplémentaires (`2 ** 3 ** 2` = 512, `"a" + 1 + 2` = `"a12"`, `1 + 2 + "a"` = `"3a"`, `1e21 + "a"`, union vers union, gestionnaires sans paramètre).
